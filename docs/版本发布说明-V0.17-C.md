### 合并分卷（不需要装 7-Zip）

```cmd
copy /b KLJyouth-office-V0.17-C-f16.gguf.part1+KLJyouth-office-V0.17-C-f16.gguf.part2 KLJyouth-office-V0.17-C-f16.gguf

```

**用 merged safetensors 的最小步骤**：合卷得到 `model.safetensors` → 把 `...-merged-config.zip` 解压到**同一目录**
（得到与 HF 目录一致的布局）→ `AutoModelForCausalLM.from_pretrained(该目录)` 即可。
若只需复现效果而不想下载 2.9 GB，**用 16.7 MB 的适配器 + 公开基座合并**更省事（见下）。

## 评测（同口径：同一批评测集、同一提示渲染、同一次跑完）

| 模型 | 宏平均 | 均衡宏平均 | 字母合规率 |
|---|---|---|---|
| **KLJyouth-office-V0.17-C** | 0.3936 | 0.3636 | 1.0000 |
| omnipilot16c（V0.16-C） | 0.3766 | 0.3489 | 1.0000 |
| omnipilot16d | **0.3937** | **0.3652** | 1.0000 |
| qwen2.5-1.5b（未微调基座） | 0.3060 | 0.3012 | 0.8516 |

**怎么读这张表（务必看）**：

- **训练确实有效**：三个微调模型都显著高于未微调基座。
- **本版与 V0.16-C 基本持平、与 16d 打平**；本轮新增的 880 条定向数据**没有**带来预期的路由增益
  （`directed_routing` 0.178，而没训过它的 16c 是 0.224）。这是**负结果**，已写入文档，不做美化。
- **多项任务低于随机且未微调基座反而更好**（`nli_score` 0.087 vs 0.338、`nli_mnli` 0.143 vs 0.229）。
  根因已定位：训练样本的标签掩码起点**错位一个助手头** —— 修复已在仓库代码里，
  但**本版适配器仍是修复前训练的**，收益需要 V0.18 重训才能验证。
- 逐任务的红色/低于随机项见 [评测报告](../docs/评测报告-V0.17.md) 与 [能力图](../docs/charts/)。

## 使用方式

```powershell
# 方式 1：直接跑 GGUF（推荐先跑这个）
ollama create KLJyouth-office-V0.17-C -f <Modelfile>   # FROM 指向 q4_K_M.gguf
ollama run KLJyouth-office-V0.17-C

# 方式 2：从适配器复现（需要 Qwen2.5-1.5B-Instruct 基座）
#   train/merge.py 里的 merge_lora(base, adapter, out) → build_gguf() → register_ollama()
```

> **两个必须知道的坑**（实测）：
> 1. **先转 GGUF 再量化**。直接从 safetensors 目录量化（Ollama 0.15.2）会产出崩溃模型。
> 2. 决策模型注册时用 **`--no-system --temperature 0`**。它的训练样本是「单条 user(决策提示) → 字母」，
>    注入 SYSTEM 会让推理分布与训练不一致，字母概率失真。
