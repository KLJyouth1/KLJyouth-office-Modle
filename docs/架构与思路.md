# 架构与思路

> 这份文档解释**为什么这样设计**。目标读者是接手这个模型仓库的人（含未来的自己）。

## 1. 一句话定位

本仓库是 **Marguerite 工作台的配套本地决策模型**：不追求"什么都会聊"，而是追求
**在低配机器上，把"选哪个工具域 / 选哪个工具 / 判是非 / 打分 / 是否该弃答"这几件事做稳**。

- 工作台源码 → [Marguerite](https://github.com/KLJyouth1/Marguerite)
- 安装包 → [Marguerite-Releases](https://github.com/KLJyouth1/Marguerite-Releases)

## 2. 决策层：Jev 式 Choice / Noul / Score

三种决策类型，构成整个模型与上层应用的契约（`decision/schema.py`）：

| 类型 | 语义 | 响应 |
|---|---|---|
| `choice` | 从若干候选里选一个（工具域 / 具体工具 / 意图 / 情绪） | 选中键 + 全候选概率分布 |
| `noul` | 判是非，返回 P(true)（是否蕴含 / 证据是否足够） | 概率，0.5 阈值判是非 |
| `score` | 按**有序**等级打分（支持程度：矛盾 < 中立 < 蕴含） | 等级下标 + 概率分布 |

### 2.1 为什么是"只答字母"，而不是让模型输出候选原文

决策引擎走 **prefill-only**：把候选渲染成 `A) … B) …`，只解码极少量 token，
从 `logprobs` 里读各字母的概率。**一次请求 = 一次决策**，省掉解码等待。

字母一定是单 token（ASCII），不会因中文/多 token 候选被拆开，从而保证
**概率能一对一映射回候选**。若让模型输出候选原文，一个中文候选会被拆成多个 token，
概率无法回填。

> 反面教训（实测）：未经字母约定训练的原模型，首 token 会是**候选原文**（如 `media`），
> 此时按字母取概率会**静默给出错误结论** —— 这就是 `letter_ok` 存在的理由：
> 它不修 bug，它把"概率不可信"这件事**暴露出来**，让上层回退。

### 2.2 训练与推理必须逐字同构

训练样本的提示由 `decision.engine.build_prompt` 渲染，评测与线上推理**走同一个函数**。
整个项目只有这一份提示模板，避免训练/推理漂移（历史上候选顺序漂移过一次，见下文）。

### 2.3 三个必须记住的实测坑

1. `num_predict=1` 会让 Ollama **丢掉 logprobs**（qwen3 必现）→ 固定取 2，并显式处理异常。
2. 思考型模型（qwen3）首 token 是推理词（`We`/`First`），`think=false` 无效 → 必须靠 `letter_ok=False` 识别并回退。
3. **标签掩码起点错位一个助手头** → 见 [工程日志](工程日志-训练与根因.md#根因标签掩码起点错位一个助手头已修待重训验证)。
   它让"训练时该在哪个位置学字母"与"推理时读哪个位置的概率"错开，是本轮最有价值的发现。

## 3. 能力地图

### 3.1 基础 11 类（V0.16 引入，V0.17 沿用）

| 任务族 | 来源 | 为什么需要 |
|---|---|---|
| `routing` / `tool_choice` | 本项目 demo 轨迹 | 工具域与工具级路由，**线上真正被消费** |
| `intent_massive` / `intent_clinc` | MASSIVE / CLINC150（含域外 OOS） | 意图识别，含"这句话不属于任何已知意图" |
| `emotion6` / `emotion28` | dair-ai/emotion / GoEmotions | 情绪，用于自适应语气与升级判断 |
| `fact_vitaminc` / `fact_evidence_noul` | VitaminC | 证据对主张的支持关系 + "证据够不够" |
| `nli_mnli` / `nli_noul` / `nli_score` | MNLI | 蕴涵关系与**有序**支持程度 |
| `abstain` / `grounded` | 合成（主体×数值组合扩容） | 抗幻觉：无据要敢说"不够"，有据要敢答 |

`abstain` 与 `grounded` **共用同一条指令**——这是刻意的：模型无法靠措辞区分二者，
只能真的去读 state 里有没有证据。（历史教训：曾把答案写进题目里，模型学到的是措辞捷径而不是判断。）

### 3.2 定向四域（V0.17 新增）

覆盖用户真正要求的方向：**电脑/系统操控、办公软件、3D 建模、视频与图像、代码**。

- `directed_routing`：句式与线上 `agent/router.py` 的六域 choice **完全同构**，六域各 100 条。
- `directed_tool_choice`：域内 **45 个真实工具**的细粒度选择（工具名逐一取自 `tools/*.py`，不臆造）。

> **本轮的负面结论**：这 880 条**没有**带来预期的路由增益，且只学会了 browser 一域。
> 详见 [评测报告 §5](评测报告-V0.17.md#5-结论含对本轮实验的负面结论)。保留这批数据仍然有意义：
> 它是**可复现的负结果**，也是下一轮"别只靠表面线索"改进的基线。

## 4. 低运行环境优先（硬约束下的取舍）

目标机器是 **RTX 3050 Ti Laptop / 4GB VRAM**，这决定了一切取舍：

| 决定 | 理由 |
|---|---|
| 只训 ≤1.5B，且必须 4-bit QLoRA | 4GB 显存放不下更大的可训练模型 |
| 只训 LoRA 适配器（17MB），不碰全量权重 | 训练成本与显存都可控；基座可替换 |
| 交付走 GGUF + `q4_K_M`（986MB） | f16 的 3.1GB 在 4GB 卡上会溢出到内存并拖死请求；q4 能 100% 进显存 |
| 量化路径固定"先转 GGUF 再量化" | 直接从 safetensors 量化会产出崩溃模型（Ollama 0.15.2 实测） |
| 显存分配用默认分配器 | `expandable_segments` 会触发内部断言；`cudaMallocAsync` 慢 2.3 倍 |
| 不用 `device_map="auto"` | 会把层卸载到 CPU，1.5B 直接掉到 20~47 s/step |

**不做虚假承诺**：7B / 万亿参数 / 全模态 / 世界模型在本地训练物理上不可行。
这类能力只能以"接入 + 编排"的方式获得，不属于本仓库的训练成果。

## 5. 模型如何被工作台消费

```
Marguerite（Rust 引擎 + Tauri 桌面 + Web 控制台）
   └─ 模型档案 models.json（云 / 本地 / 自定义三类接入点）
        └─ Ollama 本地接入点 ──> 本仓库产出的 GGUF（omnipilot17:latest）
             └─ 决策调用：Jev 式 Choice/Noul/Score（读字母 logprob）
```

两条**接入前提**（缺一则模型在工作台里不可用）：

1. **注册为本地档案**：`kind=local`、`base_url=http://127.0.0.1:11434`（Ollama 的 OpenAI 兼容端点）。
2. **进档位候选链**：工作台的档位分层（旗舰 / 均衡 / 极速）用「档内有序候选链」选后端，
   链在 `tier_rules.json` 里（数据驱动）。本地小模型因上下文与单价特征，天然落在**极速档**；
   若要它参与某档回退，需要把它的档案 id 加进该档链里。

> 工作台侧的档位治理与本地档案部署代码在 [Marguerite](https://github.com/KLJyouth1/Marguerite) 仓库，不在本仓库。

## 6. 设计原则（本仓库的纪律）

1. **诚实优先于好看**：概率不可信就报 `letter_ok=False` 让上层回退，绝不静默给错结论；
   评测中低于随机的任务必须标红，不许从图里删掉。
2. **可复现**：固定随机种子（`20261016` / `20261017`）、数据与统计随仓库入库、图表可从报告一键复现。
3. **单一事实来源**：域名说明（`DOMAIN_DESC`）、候选渲染、判分口径各只有一处实现，避免上下游漂移。
4. **不臆造**：工具名必须取自真实工具清单；失败要写清失败原因，不编造备用后端、不伪造结果。
5. **脚本路径以文件位置为基准**：不依赖运行时工作目录（本仓库所有脚本遵守）。
